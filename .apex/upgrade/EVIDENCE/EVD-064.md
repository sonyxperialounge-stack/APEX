## Context

27 defines self-healing as evidence-driven recovery: canonical classes,
equivalent-attempt fingerprints, bounded escalation to BLOCKED. 45 §2.8
owns the codes (`EQUIVALENT_ATTEMPT_BLOCKED`, …). Done-when is RCV-T01..T06.

## What was built

- `~runtime/src/engines/warden.ts` (+pure ladder, existing supervision
  untouched): `RECOVERY_FAILURE_CLASSES` (27 §2, 19 classes),
  `fingerprintAttempt` (sha256-16 over action+command+cwd+inputs+env),
  `checkEquivalentRetry` (second identical print needs a documented changed
  prerequisite, else `EQUIVALENT_ATTEMPT_BLOCKED`), `classifyRecoveryFailure`
  (known codes map; all else stays UNKNOWN — never invented),
  `planRecovery` (SCHEMA_FUTURE→read-only/never-downgrade; SKILL_STALE→
  stage-patch/never-in-place-rewrite; HOST/CAPABILITY→one bounded refresh;
  locks→bounded retry; UNKNOWN→capture-diagnostics; bounded attempts→
  escalate-blocked), `validateRecoveryStrategy` (a check-dropping strategy
  without a requirement change is refused), `LadderRecoveryRecord` +
  `buildRecoveryRecord` (27 §14 shape; named `Ladder…` because the
  capability-registry `RecoveryRecord` already owns the bare name).
- `+runtime/test/engines/recovery.test.ts` (6): RCV-T01 no-loop gate,
  RCV-T02 never-downgrade, RCV-T03 stage-not-rewrite, RCV-T04 bounded
  refresh + spent-escalation, RCV-T05 check-deletion refused, RCV-T06
  unknown stays unknown with a 16-hex print.
