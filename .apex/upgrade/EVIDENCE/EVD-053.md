# EVD-053 — Capability search + compact index (WP-053)

Date: 2026-09-11 · Packet: WP-053 · Branch: upgrade/army-v4 · Dep: WP-051

## Context

22 §2: the Level-A compact index is id + one-line summary + effects. 22 §3:
search rank over id/title/aliases/description/tags/effects/platform via
tokenized lexical scoring with exact-id/alias bonuses. 22 §5: the schema
budget is the authority — the index must not grow with the catalog. 54 §4:
whatever does not fit is DEFERRED, named honestly, and reachable through a
per-capability describe door (TLS-T07: unavailable capabilities are withheld).

## What was built

- `+src/engines/capability-search.ts` (pure in-memory, zero-dep — no exec,
  no disk):
  - `CapabilitySearch.search(query, {limit, onlyAvailable})` — deterministic
    scorer: exact canonical id (1,000,000) > exact alias (500,000) > id-prefix
    (250,000) > weighted token overlap over id/aliases/title/description/
    effects/platforms (22 §3 weights 10/8/5/3/4/2). Ties break on canonical id
    ascending, so ranking is identical across runs and hosts. `onlyAvailable`
    defaults to true (unavailable capabilities are invisible, never fabricated).
  - `CapabilitySearch.describe(id)` — the tier-2 door (54 §4): resolves the
    full descriptor through `registry.select`; null for missing or unavailable
    (TLS-T07).
  - `CapabilitySearch.compactIndex(budgetTokens)` — id-ascending Level-A index,
    greedy-filled via `estimateTokens` (cortex.ts, chars/4) within the
    `capabilities.schemaBudgetTokens` budget. Honest remainder: `deferred`
    counts every capability that exists but did not fit; budget ≤ 0 defers
    everything with an empty index. One entry per canonical id.
- `~src/core/types.ts`: `ApexCapabilitiesConfig.schemaBudgetTokens: number`
  (44 §3, default 1000).
- `~src/engines/ledger.ts`: DEFAULT_CONFIG carries `schemaBudgetTokens: 1000`;
  both merge sites spread DEFAULT_CONFIG.capabilities, so the key reaches every
  loaded config automatically.
- `~templates/config.json` + `~runtime/payload/templates/config.json`:
  `"schemaBudgetTokens": 1000` + a `_capabilitiesNote` sentence saying what
  the budget caps and how deferred schemas are reached.
- `+test/engines/capability-search.test.ts`: 18 tests (see below).

## Surprises

1. The tokenizer originally split on `/\W+/`, which keeps underscores glued:
   `host.delete_file` never matched the query "delete file" and lost to
   `host.delete_all` on the id-ascending tie-break. Splitting on
   `/[^a-z0-9]+/` (dots, underscores, hyphens separate tokens) restored real
   search quality; exact-id/alias bonuses live before tokenization so they are
   unaffected. Fixed in code, confirmed by the multi-token test.
2. `CapabilityDescriptor` has `title`, not `summary`; `source` requires `kind`;
   availability changes arrive as re-registration (there is intentionally no
   `setAvailability` mutation). The first test draft assumed a different
   detail shape — corrected against the real registry API.
3. Legal effects do not include "SEARCH"/"MODIFY"; the synthetic catalog now
   cycles READ/WRITE/EXECUTE/NETWORK/INSTALL.
