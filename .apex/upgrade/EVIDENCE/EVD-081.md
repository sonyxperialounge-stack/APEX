## What changed in the workflow

2. **Windows first-class** (kept and strengthened): `windows-latest` leads every matrix; `fail-fast: false` so a Windows failure can never hide behind another OS.
3. **The verify job runs `npm run verify`** (sync:payload · typecheck · clean · build · test) instead of the old hand-rolled typecheck/build/test sequence — CI and local now execute the same entry point, so the step-order lesson recorded in the file header cannot regress.
4. **Payload drift guard** (new): after verify, `git -c core.autocrlf=false diff --exit-code --ignore-cr-at-eol -- payload/` must be clean. Rationale: verify syncs payload/ before testing, which would silently paper over a stale committed copy; the guard turns that into a hard failure with a `::error::` message telling the author to run `npm run sync:payload`. The eol flags make checkout line-ending conversion unable to either fake or mask drift (verified locally: fresh sync → guard clean).
5. **Packed-artifact job** (new, `needs: verify`, windows + ubuntu): `npm ci` → `npm pack --pack-destination $RUNNER_TEMP` (prepack runs sync+clean+build) → install the tarball into a clean temp project → smoke the INSTALLED artifact: `--version`, `init`, `doctor | grep "APEX Doctor"`, `gate || true` (an empty ledger must FAIL the gate) → payload/dist presence checks + no raw `.ts` ships.
