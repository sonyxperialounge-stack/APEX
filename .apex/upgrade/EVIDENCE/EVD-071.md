Date: 2026-09-11 · Packet: WP-071 (Dep WP-070) · Branch: upgrade/army-v4

## Context

B3 requires each adapter to classify the binding honestly: what the host
enforces mechanically versus what stays self-enforced. The V4 additions
(durable state, capabilities) were absent from all five adapters.
Done-when: payload sync clean; each adapter names what its host does and
does not enforce.

## What was built

A "DURABLE STATE AND CAPABILITIES" section in each of the five adapters
(no new adapter files), host-accurate and in each host's own voice:

- `opencode.md` — deepest binding: L1 tools make the global home real;
  what OpenCode does not enforce is truthful *description* of durable
  writes and honest unavailability for unrun calls.
- `claude-code.md` — CLAUDE.md mirrors project memory only; what Claude
  Code does not enforce: hooks guard project paths but not the global
  home, and a Task model that cannot load is still your problem.
- `cli-generic.md` — headless mode: what a CLI host does not enforce is
  any awareness of the home; resolve READ_WRITE/READ_ONLY/VOLATILE before
  claiming a durable write; sandbox probe then capability registry.
- `cursor-windsurf.md` — the honest capability list (LSP edits, gated
  terminal, no subagents) and staged-not-saved phrasing for an
  unresolvable home.
- `generic.md` — chat mode: the global home is unreachable and the
  carry-forward block is the only durable state; "remembered/saved" is a
  lie by default here; the capability list is paste-and-text.

Every section names its host's does/does-not-enforce split and points at
`core/14-DURABLE-STATE.md` / `core/16-CAPABILITIES.md`.
