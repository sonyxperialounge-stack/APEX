## Cross-check findings fixed inside this packet

1. **Global-flag leak (real bug exposed by the new surface).** `index.ts` passed the raw
   `argv.slice(1)` to every group CLI, so the consumed `--project <path>`, `--json`,
   `--repair`, `--host <name>` tokens leaked into subcommand arg lists. This collided with
   the doc's bare `memory list --project` scope switch and could swallow positionals in
   `skills` (its positional skips a `--` token AND the following token). Fix:
   `groupArgs(argv)` strips consumed global pairs/switches centrally for all five group
   commands, but keeps a BARE `--project` for the memory scope switch.
2. **Bare-flag presence bug (latent, now exposed).** `flag("--user-override") !== undefined`
   reads the flag's VALUE, so a bare flag at the end of argv read as absent. It had only
   ever worked because the leaked `--project <path>` followed it. `promote` and
   `reset --restore` now test presence with `args.includes(...)`; message text names the
   canonical 53 §3 spelling `--i-accept-unverified`.
3. **Migrate self-copy guard.** With APEX_HOME unset, the deprecated ARMY_HOME alias can
   resolve the CURRENT home to the very directory being migrated; `migrate-from-army` now
   refuses that degenerate case in plain language instead of writing a meaningless marker.

## Surprises

- This machine really has a legacy `~/.army`; the first version of the migrate test
  deleted ARMY_HOME from the child env and therefore reached the REAL user default. The
  test now points ARMY_HOME at a non-existent temp path for the "nothing to migrate"
  case, and the suite never touches real user state.
- `skills-cli.ts` grew past 700 lines but stays under the MOD-T05 ≤1400 ceiling for
  `tools.ts`-class modules (the budget binds the MCP tool module; CLI modules keep their
