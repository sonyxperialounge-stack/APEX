# EVD-074 — WP-074: Templates and config migration (44 §§1–6)

## What was built

- **V4 config types** (`src/core/types.ts`, per 44 §3): `MEMORY_WRITE_POLICIES`,
  `MEMORY_NOTIFICATIONS`, `ARCHIVE_DETAIL`, `PROJECT_SKILL_MODES`, `LEARNING_SCOPES` consts;
  new optional groups `ApexMemoryConfig` / `ApexArchiveConfig` / `ApexLearningConfig`;
  `ApexContextConfig` += `learnedContextTokens`, `freezeHotSnapshot`; `ApexSkillsConfig` +=
  `enabled`, `useGlobal`, `projectSkills`, `autoPromote`, `maxIndexTokens`;
  `ApexCapabilitiesConfig` += `discovery`, `lazySchemas`, `aliasOverrides`; `ApexConfig` +=
  optional `schemaVersion` / `memory` / `archive` / `learning`. Optional at the type level —
  a V3 file typechecks; the resolver applies defaults.
- **The ONE merge** (`src/engines/ledger.ts` `loadResolved()`, 44 §1): project > global home
  (`<APEX home>/config.json`) > defaults. Narrowing exceptions implemented exactly:
  autonomy takes the MORE RESTRICTIVE layer (CFG-T03); `doNotRead`/`doNotTouch`/`ignore`/
  `sourcesOfTruth` union across explicit layers and `allowedPaths` intersects (CFG-T04).
  A silent layer contributes nothing — an explicit value replaces the default outright.
- **ResolvedConfig with provenance** (CFG-T09): `layers[key] ∈ {project, global, default,
  project+global}` for every key; loadConfig() delegates to loadResolved().
- **MIG-config-1-to-2** (44 §6): on load, a project config with no `schemaVersion` is
  backed up (`json.ts backup()` → `.apex.bak`), gains ONLY `schemaVersion: 2` (prepended,
  every existing key and `_comment` kept in order), under the `.apex/locks/config-migrate.lock`
  cross-process lock, with a `MIG-config-*` COMPLETED record appended to
  `.apex/migrations/journal.json`. Idempotent (second load rewrites nothing); a FUTURE
  generation is read-only and reported, never downgraded (29 §7).
- **Unknown-key reporting** (CFG-T05): both files' unknown keys now carry the SOURCE FILE
  path and a nearest-key SUGGESTION (edit distance ≤ 2), top-level and nested sections
  (recursing into `delegation.models`, preserving the old legacy auto-migration behaviour).
- **Trust decision gate** (`src/stores/trust-store.ts`, CFG-T08 / REQ-SKL-018): a `review`
  scan verdict now ALWAYS requires the explicit override + recorded justification —
  `TRUST_EXPLICIT_DECISION_REQUIRED` without it. No unattended path to trust exists in any
  autonomy mode. (Deny remains absolutely non-overridable.)
- **Template** (`templates/config.json`, synced to payload): `schemaVersion: 2` first, the
  full V4 surface with per-group `_note` documentation keys. Templates/*.md needed no change
  (no config references).

## Surprises / cross-check notes

- The old `normalise()` silently DROPPED unknown keys inside sections it did not know
  (`memory`, `archive`, … would have been ignored entirely before this packet added them to
  DEFAULT_CONFIG); the new generic section walker reports them.
- Extension-trust and hook-consent already took an injected `scanCached` dep, so the
  cache extraction was a pure re-plumb (`scanCached: cache.scan`), no behaviour change.
- `suggestKey` is case-insensitive and bounded at distance 2 — the CFG-T05 test's original
  nested typo (`maxSubagentRetry`) is distance 3 from its target, so the test uses a real
  near-miss instead of asserting a suggestion the policy intentionally withholds.
