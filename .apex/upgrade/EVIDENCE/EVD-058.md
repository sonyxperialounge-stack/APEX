## Context

- **Doc 54 §2 (amending 22 §3)** — the third bridge function: `CapabilityBridge { search(query, limit?), describe(ids) → {found, notFound}, invoke([{id, arguments}]) }`. Invoke is NOT an authorization path — it resolves the descriptor, maps effects through `toOperationKind` (42 §6, one mapping) and asks the Governor exactly as a direct call would. A deferred tool is not a cheaper tool.
- **Doc 54 §3–§4 (amending 22 §5, 32 §3)** — three-tier disclosure: tier 0 (all records eager when the full catalogue fits the budget), tier 1 (bridge + compact manifest of names, grouped by source), tier 2 (bridge + one summary line per source). Budget = `min(capabilities.schemaBudgetTokens, 25% of context.budgetTokens)` via `estimateTokens`, re-evaluated EVERY assembly, never once at boot. Policy inverted: "be eager whenever it fits"; never defer core governance tools; never defer TaskContract-required capabilities (PERF-T10).
- **Doc 22 §8** — arguments validated against the locally loaded schema BEFORE dispatch: required properties, property types, enum membership, nested objects, `additionalProperties:false`. A violation never reaches the provider's own validator.
- **Doc 54 §20** — `CAPABILITY_NOT_IN_CATALOG`, `CAPABILITY_ARGS_INVALID` (+ `CAPABILITY_BLOCKED`, `CAPABILITY_CALL_FAILED` for the outcomes the bridge itself reports).
- **WP-055 interplay** — a dispatcher rejection with code `TOOL_NOT_FOUND` marks the capability DEGRADED in the registry; no pretend call is ever issued twice (CAP-T05).

## What was built

- **`+src/engines/capability-bridge.ts`** — `CapabilityBridge` (search delegates the WP-051 search engine; describe batches per-id with the mayExpose gate — one unknown id lands in `notFound`, never fails the batch, TLS-T09; invoke resolves each call independently: not-in-catalog / not-exposed → `CAPABILITY_NOT_IN_CATALOG`, schema load failure or local validation violation → `CAPABILITY_ARGS_INVALID` (TLS-T10, dispatcher never called), Governor decision → `CAPABILITY_BLOCKED` with the rule named + `ask` flag for MANUAL/GUARDED, absent invoker → honest refusal, dispatcher `TOOL_NOT_FOUND` → `markStructuralFailure` then `CAPABILITY_CALL_FAILED`). `validateArgsAgainstSchema` exported for the host adapter, plus `operationOf` carrying path/command/url args into the Operation for Governor path rules. Pure in-memory; the bridge executes nothing itself.
- **`+src/engines/capability-disclosure.ts`** — `assembleDisclosure(registry, {schemaBudgetTokens, contextBudgetTokens, requiredIds})` → `{tier, text, deferred, mandatory, usedTokens, budgetTokens}`. Deterministic tiers with the budget as authority; unique AVAILABLE per canonical id (most-trusted wins); CORE-trust and `requiredIds` never deferred and always spelled out even at tier 2 (PERF-T10 seam — the TaskContract lifecycle feeds it in WP-060); tier 2 carries per-source counts + the bridge search hint so the catalogue stays usable (TLS-T11); empty registry → honest "no capabilities are currently available on this host." (CAP-T05).
- **`~src/plugin/index.ts`** — new `capabilitySurface(e, {loadSchema?, invoker?})` following the `hookScriptRegistry`/`extensionSurface` pattern: builds the search + bridge over the bootstrapped registry/governor, exposes `bridge.search/describe/invoke`, `disclosure()` (reads `e.cfg.capabilities?.schemaBudgetTokens` and `e.cfg.context?.budgetTokens` live at each call), and `registry.all/select`. The host adapter plugs its schema loader and dispatcher; without them search/describe still work and invoke refuses honestly. Governor decisions route through `onDecision` → `event("plugin.block", {tool, rule})` on blocked (non-ask) calls (TLS-T08 auditability).
- **`+test/engines/capability-bridge.test.ts`** (18), **`+test/engines/capability-disclosure.test.ts`** (12), **`+test/plugin/capability-surface.test.ts`** (2) — see acceptance mapping.

## Surprises

- The bridge's local-schema test hit schema validation BEFORE the blocklist: with the default `loadSchema` (READ_SCHEMA), writing to `config/prod.yaml` failed with `CAPABILITY_ARGS_INVALID` (missing `content`) instead of `CAPABILITY_BLOCKED` — precedence is by design (22 §8 validation precedes governing, and the block test now binds WRITE_SCHEMA). Tests must bind a per-capability schema for blocked-call assertions.
- Tier 1 only opens when full records exceed the budget while compact names fit — with 3 slim records (no platforms/aliases) the full catalogue is cheaper than any manifest, so the tier never engages at the default 1000-token budget. Tests exercise the band with fattened records (platforms+aliases) and a tight context budget; at 240 context tokens the same catalogue is tier 1, at 200 it is tier 2 (the budget is the authority).
- `sourcescan.test.ts` "imports only node:+relative" flags any `from "…"` string anywhere, including the disclosure header's quotation "INVERTED from \"defer when large\"" — reworded to "defer when large" became "be eager whenever it fits". Watch for quoted-from prose in doc comments of new files.
- `CapabilityInvoker["call"]` is a method type, not `CapabilityDescriptor` — the recording `calls` array must be typed `CapabilityDescriptor[]` (TS2345 otherwise).
- plugin surface test boots real engines (`bootstrapEngines`) with their archive/openCode home paths; `setLogDir` keeps events out of the user's state, and the surface test adds ~1s to verify.
