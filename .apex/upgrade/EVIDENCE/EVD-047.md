# EVD-047 — WP-047b archive dir, pinning, curator min-interval

Date: 2026-09-11
Branch: upgrade/army-v4

## Context

Inspection found the WP-047b engine surface ALREADY implemented and tested in the tree:

1. **Archive, never delete (54 §9.3)** — `skill-curator.ts` retirement MOVES the skill body
   to `<skillsRoot>/.archive/<name>-<version>/`; the `skills retire` CLI reports exactly
   where it went and states "Nothing is deleted." The test asserts the archived copy
   exists with its SKILL.md intact.
2. **Curator min-interval (54 §9.5)** — `runCuration` takes `lastCuratedAt` +
   `minIntervalHours` (default 168) and returns `{ ran: false }` without touching anything
   when the interval hasn't elapsed; the timestamp persists in `<skillsRoot>/.state.json`
   (LIFE-T08).
3. **Pinning engine (54 §9.4)** — the curator reads a `.pinned` marker file beside
   SKILL.md and skips pinned skills outright (never stale-mark, never archive), reported
   with its reason (SKSEC-T09).

The ONE missing surface was the CLI: 54 §9.4 calls for `apex-agent skills pin <name>` to
create the protection, and `53 §3` lists `skills pin` among the shipped commands — but the
skills CLI had no `pin`/`unpin`. Added:

- `skills pin <name>` — writes a `.pinned` marker through the write chokepoint
  (`core/json.ts` writeText, per CORE-005), protects the skill from automatic staleness
  and archival.
- `skills unpin <name>` — removes the marker.
- `findSkillDir()` resolves a header name to `<skills>/<category>/<name>/SKILL.md`.
- `usageSkills()` documents both commands.

Root-cause fix during the pass: the first draft wrote the marker with `fsp.writeFile`,
which the CORE-005 source scan correctly refused — every disk write must go through
`json.ts`/`log.ts`. The fix routes the marker write through `writeText` (unpin's
`fsp.rm` is a delete, matching the `retire`/rename precedent).
