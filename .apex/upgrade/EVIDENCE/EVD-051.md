# EVD-051 — Capability registry (WP-051)

Date: 2026-09-11 · Packet: WP-051 · Branch: upgrade/army-v4

## Context

Implemented the capability registry per 21 §4–§5 and 47 §4.9
(`engines/capability-registry.ts` + tests). The registry is the normalization
layer between arbitrary host tool names and stable ARMY concepts — descriptive
and policy-aware, it does NOT execute tools.

## What was built

- `CapabilityDescriptor`, `CapabilityAvailability`, `CapabilityTrust`,
  `CapabilitySource`, `ExposureContext`/`ExposureDecision` types.
- `normalizeCapabilityId` — trimmed, lowercased, whitespace-collapsed canonical
  form for ids AND aliases.
- `inferEffects(name, description)` — conservative inference fallback (21 §5):
  unknown/empty classification lands on `EXTERNAL_SIDE_EFFECT`, never an
  optimistic "reads only" (CAP-T02).
- `mayExpose(cap, ctx)` — 21 §7 exposure policy: availability gate, REVOKED
  gate, UNTRUSTED+DESTRUCTIVE gate. Exposure is separate from execution — the
  Governor still decides execution (CAP-T04 holds structurally: the registry
  has no execute path).
- `CapabilityRegistry` — register (with alias index: aliases route to the
  canonical id), candidates (multi-vendor for one semantic id — CAP-T01),
  isAvailable, select (AVAILABLE-only + trust-ranked, deterministic tie-break),
  all, bounded refresh (once per reason, no polling — 21 §9), and
  `toOperationKind` delegating to the governor adapter (47 §4.9: the ONLY
  bridge to the Governor).
- Validation: unknown effect/availability/trust values are refused with
  `BAD_CAPABILITY` (CAP-T07 — the taxonomy is imported from core/types.ts).

## Verify

`npm run verify` -> 1052 pass, 0 fail, exit 0 (32.8s).

## Acceptance mapping

| Id | How |
|---|---|
| CAP-T01 | same semantic host tools normalize to same canonical id (two vendors for `fs.read`, alias routing `grep`/`rgrep` → `fs.search`) |
| CAP-T02 | unknown external tool is not inferred read-only; `zorp_quantum_sync` → EXTERNAL_SIDE_EFFECT |
| CAP-T03 | lookups perform zero tool execution — module imports no exec path, no disk I/O; pure in-memory maps |
| CAP-T05 | unavailable capability named UNAVAILABLE (with reason) and not selectable; absent id returns null, no pretend call |
| CAP-T07 | registry validates effects against the ONE taxonomy from core/types.ts |

## Surprises

1. The alias-index bug was mine: aliases were stored on descriptors but never
   indexed, so alias lookups returned nothing. Added `aliasIndex` (normalized
   alias → canonical id) rebuilt on re-registration.
2. `inferEffects("http_get")` yields READ+NETWORK, not NETWORK-only: "get" is
   the READ pattern, and READ is defined as observing local or REMOTE state
   (21 §3) — the inference was correct, my initial expectation was wrong.
