## Context

The 13-tool target set from 40 §15, added only after WP-053's compact-index
budget was enforced. Done-when: all existing tools keep their contracts and
the new ones have tests.

## What was built

- `+runtime/src/mcp/state-tools.ts` — the 13 tools (definitions + dispatch
  + helpers) in their own module, because MOD-T05 caps tools.ts at 1400
  lines and the budget's own instruction is "split the module". Invariants
  in the module doc: stored text carries a data-not-policy note (48 §4),
  refused writes say REJECTED and never imply success, and a missing
  home/registry degrades with the honest-unavailability statement.
  `archiveDirFor` moved here (shared, exported).
- `~runtime/src/mcp/tools.ts` — slimmed to the legacy surface (1130 lines):
  `TOOLS = [...TOOLS_CORE, ...STATE_TOOLS]`; dispatch delegates to
  `dispatchStateTool` first and falls through otherwise.
- `~runtime/src/mcp/server.ts` — the discovery registry now travels with
  every `tools/call` so the capability tools can serve it.
- `+runtime/test/mcp/state-tools.test.ts` — 23 tests: registration
  uniqueness, VOLATILE-home honesty (read creates nothing), stage→commit
  round-trip, injection-text refusal at stage and correct, reject path,
  correction supersession, session search/read with provenance, unknown
  session refusal, skill index without body leakage, view-as-data, lint
  refusal, security-gate absoluteness, userOverride promotion recorded
  unverified, capability serve/describe/unknown/no-registry degradation,
  doctor read-only run.
