# EVD-056 — WP-056 Extension contract (23; EXT-T01..T07)

**Date:** 2026-09-11
**Branch:** `upgrade/army-v4`
**Dependencies:** WP-051 (capability registry), WP-042 (hash-bound trust), doc 23, 54 §15
**Verify:** `npm run verify` → 1200 pass, 0 fail, exit 0 (~40s)

## Context

- **23 §3** — discovery is not enablement: `DISCOVERED -> SCANNED -> TRUST_PENDING -> ENABLED (↔ REJECTED)`, `ENABLED + hash drift -> TRUST_PENDING`.
- **23 §4** — manifest-first, data-only parse; entry loading only after policy/trust checks.
- **23 §5** — trust record bound to the executable content hash; any drift invalidates.
- **23 §6** — project-controlled extensions stay disabled until explicitly trusted; project documents can never grant trust to themselves.
- **23 §7** — external extension directories: reject with `UNSUPPORTED` honestly if not implemented.
- **23 §8/§9** — extensions request mutations through ARMY policy APIs; NETWORK/EXTERNAL_SIDE_EFFECT never silently downgraded.
- **23 §10** — scanner is a risk filter, not a sandbox (path traversal, hashes).
- **23 §11** — failure isolation: capture redacted error → disable invocation → mark capability DEGRADED → continue; repeated crashes → session quarantine.
- **54 §15** — hook/extension consent: "the same mechanism as extension trust, not a second one".

## What was built

### Trust store layer (`src/stores/trust-store.ts` + new `src/stores/extension-trust.ts`)

- `ExtensionTier = "USER" | "PROJECT" | "EXTERNAL"`, `ExtensionTrustGrant` bound to the ENTRY content hash (23 §5), persisted in its own `trust/extensions.json` (skill and extension grants never mix).
- `grantExtension`: refuses `PROJECT` tier claimed by project content — `EXTENSION_SELF_TRUST_REFUSED` (EXT-T02, 23 §6); extension-context scanner `deny` never overridable (`EXTENSION_SCANNER_DENY`); `review` override requires a recorded justification (`MISSING_JUSTIFICATION`). Same cross-process lock as skills (54 §15).
- `extensionStatus(extensionId, contentHash)`: exact-hash → trusted; stale hash → TRUST_PENDING reason "content hash changed since the recorded grant"; none → no trust (EXT-T03).
- `scanExtension` uses the strict `extension` scan context with the `ext:` cache namespace — the extension context already existed in `redact.ts` with deny severities and had no consumer before this packet.
- Split into `extension-trust.ts` (injected `scanCached`/lock/clock from the trust store) to keep both store files under the 350-line module budget (MOD-T05) — 327 + 201 lines.

### Plugin surface (`src/plugin/extensions.ts`, new)

- `EXTENSION_MANIFEST_VERSION = 1`, `EXTENSION_API_VERSION = "1"`, `parseExtensionManifest` — pure data parse: id/entry path-traversal refusal, taxonomy-only effects, apiVersion drift → `EXTENSION_API_UNSUPPORTED` (23 §8).
- `discoverExtensions` — data-only discovery (EXT-T01): reads manifest.json, validates, hashes the entry file (sha256, 16-hex). NO import/eval/exec path exists anywhere in the module. Malformed packages are REPORTED as problems, never silently dropped.
- `evaluateExtension` — the 23 §3 lifecycle ladder over the trust store; scanner-deny → REJECTED; missing entry → DISCOVERED; hash drift → TRUST_PENDING.
- `extensionOperationFor`/`requestExtensionOperation` — extension mutation = an ordinary `Operation` through the SAME Governor (`toOperationKind` + `decide`, EXT-T04); NETWORK → network kind, EXTERNAL_SIDE_EFFECT → deploy kind, DESTRUCTIVE stays visible — never downgraded (EXT-T06).
- `reportExternalDirectories` — every configured external directory answers `UNSUPPORTED` honestly (EXT-T05, 23 §7).
- `openExtensionQuarantine` + `invokeExtension` — crash-isolation wrapper (EXT-T07, 23 §11): throw → redacted error → `markStructuralFailure` (capability DEGRADED, 21 §10) → repeated crashes quarantine for the session. The wrapper never re-throws raw extension errors.

### Wiring (`src/plugin/index.ts`)

- `extensionSurface(projectRoot)` exposed from the plugin: `discover` (data-only), `externalDirectories` (honest UNSUPPORTED), `quarantine` (session). Loading lands with the WP-058 invoke bridge.

## Surprises

- **Module budget (MOD-T05):** the trust-store grew to 439 lines and tripped the hard 350-line ceiling with no grandfathering. Fixed by splitting the extension subsystem into `extension-trust.ts` with dependency injection (shared scan-cache writer + cross-process lock stay single-owned by the trust store — 54 §15's "one mechanism" is preserved structurally).
- **`Decision` has no `verdict`/`kind` fields** — only `allowed`/`ask`/`rule`/`reason`. The tests assert on the real surface.
- **`redact()`** strips real secret shapes (sk-ant-…, Bearer…), not bracketed placeholders; the redaction test uses a real Anthropic-shaped token.
- `scanAndEvaluate` of a clean, untrusted entry yields TRUST_PENDING (row 3 of the ladder), not SCANNED — the scan and the lifecycle are two steps.
