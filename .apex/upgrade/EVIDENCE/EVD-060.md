# EVD-060 — WP-060 TaskContract envelope + governed task loop entry (25, 41 §15)

Date: 2026-09-11 · Packet: WP-060 (Dep WP-029, WP-049, WP-057) · Branch: upgrade/army-v4

## Context

25 defines the envelope-only rule: TaskContract is the active-objective
envelope; acceptance obligations stay in the existing Ledger requirements. No
second goal database (TASK-T01). Resume validates against the project
fingerprint (TASK-T03). Parent/child ids with the parent Gate owning
completion (TASK-T04). Mid-task correction is an auditable supersession that
never edits old evidence (TASK-T05). Handoff is pointer-rich, never a history
copy (TASK-T06). Resumable tasks survive model replacement with no heartbeat
(TASK-T02, AUT-T05). 41 §15 is the creation blueprint, adapted to the real
`OperationKind` set (42 §6) and the injected-clock rule (47 §5).

## Surprises

- Deterministic ids collide on identical injected inputs by design (43 §7):
  parent and child created with the same fixed `now`/`random` shared one
  TASK id and the self-parent guard correctly refused the child. The test now
  advances the child clock (`now+1`, different random) — production callers
  use the wall clock + entropy so this never occurs live.
- `npm run test:unit -- <file>` ignores the file filter in this repo (script
  hard-codes its two globs); it still runs the full core+engines set (871
  tests). The packet gate remains the full `npm run verify` (1272 tests).
