# EVD-046 — WP-042b source tiers, scan caching, deny never overridable

Date: 2026-09-11
Branch: upgrade/army-v4

## Context

Inspection found the WP-042b surface ALREADY present in the tree (the model that closed
the earlier packets also implemented the 54 §9 pieces: `SkillTier`, `grant()` scanning
with deny/review routing, and the deny-never-overridable message). WP-042b was still
PENDING in STATE.json, so the packet's remaining work was the 54 §9.2 scan-cache
enforcement:

1. **SKSEC-T07 scan caching** — `scanSkill` now scans through a disk cache keyed by the
   CONTENT hash (16-hex sha256) plus the scanner policy version. An unchanged skill is
   not re-scanned on the second boot; one cache file covers ALL skills (`scan-cache.json`
   under `trust/`), and only verdict + rule names/severities are stored — never excerpts,
   so an old excerpt can never leak back out of the cache.
2. **Scanner-policy bumps** — `SCAN_POLICY_VERSION` is part of the cache key; a bump
   invalidates every cached verdict in one write, and the stale file is left in place
   (next write replaces it — nothing is deleted by invalidation).
3. **Bounded cache file** — the cache is one JSON file, entries keyed by content hash
   (16-hex prefix) with a fixed shape; no unbounded growth per boot, no new store files.

Fix during the pass: the first draft returned a module-level shared `EMPTY_CACHE`
object from `readCache()`. `scanCached` mutates `entries` in place, so a fresh boot in
the same process inherited the previous boot's entries — a false cache hit (caught by
the "second boot must re-scan" test). `readCache()` now returns a fresh object every
call; the module-level constant is gone.
