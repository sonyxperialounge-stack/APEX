# EVD-052 — Host discovery (WP-052)

Date: 2026-09-11 · Packet: WP-052 · Branch: upgrade/army-v4

## Context

22 §6–§7 + 40 §14: hosts optionally expose `listTools`/`describeTool`/
`onCapabilityChange`; discovery probes must be non-destructive (TLS-T05);
a host without the surface must still yield a usable registry (TLS-T06, 22 §10).

## What was built

- `src/host/types.ts`: secondary `HostCapabilities` interface
  (`listTools?`, `describeTool?`, `onCapabilityChange?`) + `HostToolDescriptor`
  + `NullHostCapabilities` — runtime feature detection instead of interface
  extension, so the existing `HostClient` seam and every host stay unchanged
  (40 §14). Provider credentials/models remain host-owned.
- `+src/engines/host-discovery.ts`:
  - `canonicalHostToolId(name)`: normalizes a host tool name to a canonical
    capability id — code-intelligence table (54 §14) first, otherwise the
    honest `host.<normalized-name>` fallback (22 §7). Never guesses.
  - `registerHostTools(registry, host, providerId, opts)`: the discovery
    pipeline (22 §6). A host without `listTools` contributes nothing and is
    recorded in `unknownHosts` — an empty registry, never fabricated tools.
    Declared tools register as AVAILABLE with conservative `inferEffects`
    (21 §5, unknown ⇒ EXTERNAL_SIDE_EFFECT) and trust UNTRUSTED; the
    code-intelligence table vouches TRUSTED + canonical effects (54 §14).
    Schemas stay lazy (schemaLocator preserved, never loaded). Never rejects.
  - `onHostCapabilityChange(host, refresh)`: subscribes the bounded
    registry.refresh (47 §4.9) to host capability-change events; the single
    reason is `REFRESH_REASON` so a chatty host cannot spin probes.
- `~src/plugin/index.ts`: `Engines` gained `registry` + `disposeDiscovery`;
  `bootstrapEngines` wires the registry with the null host surface (the honest
  L0 seam today) and subscribes discovery. Plugin tests exercise the new
  wiring on every boot.
- `~src/mcp/server.ts`: optional `capabilities` registry + `setCapabilities()`;
  advertise/read-only `apex://capabilities` — the compact index (22 §2: id +
  first-line summary + effects only) when a registry is attached; absent a
  registry it is neither advertised nor readable (40 §16, no fabricated L0
  service).

## Surprises

1. A config-file loader cannot carry functions (JSON) — the first draft's
   `loadHostCapabilities(configFile)` was dead code that could never yield a
   real surface; removed it and made the plugin the explicit seam.
2. `register()` normalizes aliases (lowercase), so descriptor tests must
   expect the normalized form.
3. Two genuinely different host names that normalize to one canonical id are
   two candidates (CAP-T01), not a dedup — the test now asserts that.
